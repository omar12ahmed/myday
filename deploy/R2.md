# Setting up Cloudflare R2 for MyDay

**Decided (24 Oct 2026):** stored files go in Cloudflare R2 — the Cybersecurity portfolio's images and PDFs, and
later attachments — rather than Supabase Storage. Automatic backups come first. See `specs/myday-vision.md` §6.

This guide prepares storage for private attachments, backups and public assets. Automatic backups (1.65.0) use
`myday-backups` through the `backup` Edge Function; attached files use `myday-attachments` through the `files` Edge
Function (1.68.0). Creating the buckets doesn't switch either on: each needs its token and secrets
(`supabase/README.md`).
Structured project growth is handled separately by the
[split project sync upgrade](../supabase/PROJECT_STORAGE.md) (1.44.0); R2 setup does not change the
per-record sync limit.
The app currently exports backups through `app/src/data/storage.ts`; its existing sync uses Supabase.

## 1. Create the account and activate R2

1. Create an account at [Cloudflare](https://dash.cloudflare.com/sign-up) and complete its email verification.
2. Open **Storage & databases → R2 → Overview**.
3. Review and complete R2's subscription checkout yourself, including any billing details and terms.
   Check the [current pricing and included usage](https://developers.cloudflare.com/r2/pricing/).

Cloudflare's [getting-started guide](https://developers.cloudflare.com/r2/get-started/) describes activation.
Keep passwords, payment details and recovery codes in your own password manager, outside this repository.

## 2. Create three separate buckets

From **R2 → Overview → Create bucket**, create the following. These are suggested names; use your chosen names
consistently if they differ.

| Suggested bucket | Contents | Access |
| --- | --- | --- |
| `myday-attachments` | Uploaded documents, images and other personal files | Private |
| `myday-backups` | Copies of exported MyDay data | Private |
| `myday-public` | Images, audio and downloads intended for everyone | Private during setup; public when ready |

Start with **Standard** storage. Use Automatic location unless you have a specific location or jurisdiction
requirement; resolve that before uploading real data. See [storage classes](https://developers.cloudflare.com/r2/buckets/storage-classes/)
and [data location](https://developers.cloudflare.com/r2/reference/data-location/).

Buckets are private by default. Leave **Public Development URL** disabled and add no public custom domain to
the attachments or backups buckets. A folder name inside a public bucket does not make its files private.
See [bucket creation](https://developers.cloudflare.com/r2/buckets/create-buckets/).

Alternatively, after activation, use the [Wrangler CLI](https://developers.cloudflare.com/r2/get-started/cli/).
Choose either the dashboard or these commands, so you do not try to create the same buckets twice:

```sh
npx wrangler@4 login --use-keyring
npx wrangler@4 r2 bucket create myday-attachments
npx wrangler@4 r2 bucket create myday-backups
npx wrangler@4 r2 bucket create myday-public
npx wrangler@4 r2 bucket list
```

Complete sign-in in your browser and check the intended account before creating buckets. These commands create
remote storage; they do not deploy MyDay or upload files.

For Cloudflare's optional Codex skills and MCP connection, follow its
[agent setup instructions](https://developers.cloudflare.com/agent-setup/prompt.md). Those are user-level tools,
separate from the app's dependencies. Wrangler and the MCP server use separate browser approvals; request only
the MCP permissions needed for the work. Restart Codex after adding the MCP server so it can load the new tools.

## 3. Connect each purpose separately

### Private attachments

**Status:** built as the `files` Edge Function (`specs/files.md`): presigned links signed with each file's MD5 (and its
length), a server check of each stored file's type and size, per-account prefixes, and setup steps in
`supabase/README.md`, "Attached files". The notes below are the original plan it follows.

The proposed route is **MyDay → authenticated Supabase Edge Function → R2**. The server must verify the current
Supabase user and enforce ownership for every upload, download, list and removal. An object-key prefix alone
does not provide account isolation. Supabase database Row Level Security does not automatically protect R2.

For direct browser transfers, the server can issue a short-lived
[presigned URL](https://developers.cloudflare.com/r2/api/s3/presigned-urls/) for one authorised object and
operation. Configure [CORS](https://developers.cloudflare.com/r2/buckets/cors/) for the exact website origin,
with only the methods and headers the integration uses. CORS does not replace authentication or ownership checks.
Do not put saved data, reasons, filenames or signed URLs in request logs.

An attachment feature still needs agreed upload limits, links to project/note records, deletion and offline
behaviour, and a compatibility plan for its saved fields. File contents must not be added to AI requests as
part of setting up storage.

### Backups

For an initial manual backup, use MyDay's **Export my data**, then upload the downloaded JSON to the private
backups bucket in the Cloudflare dashboard. Use a new object name for each backup so it does not overwrite
the previous copy. Keep a separate downloaded copy as well.

**Automatic backups** are built (`specs/automatic-backups.md`). Each device sends a daily copy through the
`backup` Edge Function (`supabase/functions/backup`), which writes to this bucket under the signed-in account and
keeps 14 days plus one a month for a year. "Your backups" in MyDay's footer lists, downloads and restores them,
through Import's own checks. Setting it up needs an Object Read & Write token limited to `myday-backups`, kept as
Supabase secrets (see `supabase/README.md`, "Automatic backups"). Don't add bucket expiry rules: the function does
the keeping and deleting. Attachments aren't in backups yet.

### Public assets

Only put material intended for anyone to download in `myday-public`. For production, connect an asset subdomain
under **bucket → Settings → Custom Domains**. The domain must be configured in the same Cloudflare account.
Cloudflare's `r2.dev` URL is for development and is rate-limited; it is not the production asset endpoint.
See [public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/).

Moving MyDay's existing audio is a separate app change: update its URLs and preserve its current build checks,
content audit and offline playback behaviour. Do not remove the existing files before that path is verified.

## 4. Add credentials when implementing the connection

Wrangler's browser login is sufficient for the bucket commands above. The proposed Supabase server integration
will need R2 S3 credentials. In **R2 → Manage API Tokens**, create an **Object Read & Write** token restricted to
the private buckets it needs. Keep public-asset publishing credentials separate. Avoid account-wide admin
permissions for normal file access. Follow [R2 authentication](https://developers.cloudflare.com/r2/api/tokens/).

Store the Access Key ID and Secret Access Key in the server's secret store. Use the S3 endpoint shown by
Cloudflare; jurisdictional buckets have their own endpoints. Do not paste credentials into chat, commit them,
or put them in `VITE_` variables. No R2 environment variables are currently read by MyDay, so adding them to an
app environment file alone will not enable anything.

## Before calling the setup complete

Confirm the three buckets exist and the attachments and backups buckets have no public access route. Then
verify each implemented workflow with synthetic files: private access requires the correct account; a second
account cannot access those objects; backups can be restored; and public assets load as intended.

Keep account setup, bucket provisioning and application integration distinct when reporting what works.
An authenticated CLI or an existing bucket does not establish that MyDay can upload files or make backups.
